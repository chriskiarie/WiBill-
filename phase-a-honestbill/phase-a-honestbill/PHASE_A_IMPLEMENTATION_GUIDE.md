# PHASE A: ISP Invite & Approval Flow - Complete Implementation Guide

## Overview
This phase implements the invite-based ISP onboarding flow. ISPs can only register via invitation links generated by the platform admin (Chris). After registration, accounts start in PENDING status and require approval before the ISP can access their dashboard.

## API FLOW AFTER PHASE A

### Admin generates invite (Batcave)
```
POST /api/admin/invites/generate
Headers: Authorization: Bearer {admin_token}

Response:
{
  "id": "uuid",
  "token": "secure_token_64_chars",
  "invite_link": "http://localhost:3000/join?ref=secure_token_64_chars",
  "expires_at": "2026-05-25T10:00:00Z",
  "created_at": "2026-05-18T10:00:00Z"
}

Admin copies invite_link, sends to prospective ISP via WhatsApp/email
```

### ISP validates token (before registration form)
```
GET /api/auth/join/validate?token=secure_token_64_chars

Response (if valid):
{
  "valid": true,
  "message": "Token is valid",
  "expires_at": "2026-05-25T10:00:00Z"
}

Response (if invalid/expired):
{
  "valid": false,
  "message": "Invite token has expired"
}
```

### ISP registers with invite token
```
POST /api/auth/register?token=secure_token_64_chars
Body:
{
  "email": "admin@myisp.ke",
  "password": "secure_pass",
  "isp_name": "My ISP Ltd",
  "phone": "+254700000000"
}

Response:
{
  "access_token": "eyJ...",
  "token_type": "bearer",
  "user": {
    "id": "uuid",
    "email": "admin@myisp.ke",
    "role": "isp_admin"
  }
}

Account created with:
- tenant.status = PENDING
- admin_user.onboarding_complete = false
```

### Admin approves ISP (Batcave)
```
PATCH /api/admin/tenants/{tenant_id}/approve
Headers: Authorization: Bearer {admin_token}

Tenant status changes: PENDING → ACTIVE

ISP can now:
- Login successfully
- Access dashboard
- Auto-redirect to onboarding wizard (first login)
```

### ISP rejects (status becomes SUSPENDED)
```
PATCH /api/admin/tenants/{tenant_id}/reject?reason=Spam
Headers: Authorization: Bearer {admin_token}

Tenant status changes: PENDING → SUSPENDED
ISP cannot login or access any pages
```

## SECURITY NOTES

### Invite Token Security
- Tokens are 64-character cryptographically random strings
- Tokens are unique and indexed in DB
- Tokens expire after 7 days
- After use, marked as USED (cannot be reused)
- Tokens sent via WhatsApp/email (not HTTPS yet, will fix in Phase F with TLS)

### Account Status
- Accounts created with status=PENDING
- Cannot access dashboard until status=ACTIVE
- Admin can suspend (block) at any time
- No self-approval (manual review only)

### JWT Tokens
- Admin login creates JWT with role=platform_admin
- ISP login creates JWT with role=isp_admin
- Routes check role via `@verify_platform_admin` decorator
- ISPs cannot call admin endpoints
